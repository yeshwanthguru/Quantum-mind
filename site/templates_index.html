Models of people for robots that work with them.

A robot's questions change people's answers, and asking about trust changes trust. Quantum Mind is an open-source Python library that models these effects with quantum probability, always next to the classical models it has to beat, and turns them into decisions: when to ask, which question to ask, how to fuse what the robot sees and hears, and how to hand an object over. It also runs quantum machine learning and algorithms as Qiskit circuits, offers quantum-inspired optimisers, and shows every qubit on a 3D Bloch sphere.

Three kinds of “quantum”, kept apart

Each makes a different claim and needs a different test. The library has all three, shares one problem format between them, and reports a classical baseline every time. Read the concepts page.

Quantum-like

Models of human judgement, decision and trust in quantum probability, on ordinary computers.

  • order effects, conjunction, interference
  • quantum-like Bayesian networks
  • quantum, Markov and open-system dynamics
  • quantum decision theory, contextuality, similarity
  • per-person fitting and model comparison

quantum_mind.families · quantum_mind.applications

Quantum

Gate-model machine learning and algorithms, trained on a fast simulator with exact gradients and exported to Qiskit.

  • variational and quantum-kernel classifiers
  • QAOA for any QUBO
  • VQE for Pauli Hamiltonians
  • Grover search (hardware-sized circuits)
  • Aer, IBM Quantum, Amazon Braket

quantum_mind.quantum · quantum_mind.circuits

Quantum-inspired

Classical algorithms that borrow a quantum idea. No quantum computer needed.

  • quantum-inspired evolutionary algorithm (Han and Kim)
  • quantum-behaved particle swarm
  • simulated quantum annealing
  • tensor-network classifier (DMRG sweeps)
  • classical simulated-annealing baseline

For robots that ask people questions

A robot's questions can change people's answers, and asking about trust can change trust. The robotics layer gives a robot a predicted answer, its uncertainty, and a rule for when to ask instead of act.

from quantum_mind.applications.robotics import HumanModelService

svc = HumanModelService()
svc.add_answer({'order': 'AB', 'answers': [1, 0]})
svc.query({'order': 'AB', 'ask_cost': 1.0, 'error_cost': 3.0})
# prediction, uncertainty (bits), model weights,
# {'action': 'ask' | 'act', 'reason': ...}

ROS 2 node

The same service as a ROS 2 package with standard std_msgs/String JSON topics: answers in, decisions out. integrations/ros2

Its callbacks are tested with stand-in ROS modules; it has not yet been run inside a ROS 2 installation.

What is and is not claimed

  • No quantum advantage is claimed. On the example classification task a classical model with quadratic features is the most accurate.
  • No hardware results are included yet. IBM and Braket submission code is tested against local stand-ins (a fake IBM device, the Braket local simulator).
  • All data in the examples are simulated or published aggregates, and labelled as such. No study with real people and a robot has been run yet; the validation page lists what is checked and gives a protocol for a pilot.
  • In several robotics comparisons the simulated people follow the same model the robot uses, which favours the order-aware method by construction; the tutorials say where.

Get started

pip install "quantum-mind[all]"

# quantum-like: is there an order effect?
from quantum_mind.core import compare
from quantum_mind.families.order_effects import (
    QuantumOrderModel4D, BayesOrderModel, AnchoringOrderModel, qq_test)
print(qq_test(counts))
compare([QuantumOrderModel4D, BayesOrderModel,
         AnchoringOrderModel], counts)
# quantum and quantum-inspired on one problem
from quantum_mind.problems import task_allocation
from quantum_mind.quantum import QAOA
from quantum_mind.inspired import SQA, QIEA, simulated_annealing

q = task_allocation(costs)
q.brute_force(), QAOA(q, p=3).run().energy
SQA(q).run().value, simulated_annealing(q).value

# watch a circuit on Bloch spheres
from quantum_mind.viz import circuit_trajectory, animate_bloch
animate_bloch(circuit_trajectory(qc))
